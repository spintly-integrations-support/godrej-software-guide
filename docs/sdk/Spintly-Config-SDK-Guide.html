Spintly Config SDK

The Config SDK is the SDK that talks to Spintly devices over Bluetooth. A device can be a lock, a reader, a gateway or a BLE remote. Use the SDK to:

  • set up a device
  • write passcodes
  • add fingerprints and cards
  • update firmware
  • change device settings
  • pair BLE remotes
  • put gateways on Wi-Fi

How it works: you create the SDK once and give it a token. Then you call one function at a time. The SDK finds the device over Bluetooth, does the work, saves it to the Spintly cloud, and calls you back on the main thread.

sequenceDiagram
    participant App
    participant SDK as Config SDK
    participant Cloud as Spintly cloud
    participant Device
    App->>SDK: call a function (e.g. readSoundSettings)
    SDK->>Cloud: look up the device
    SDK->>Device: find over Bluetooth, connect, send command
    Device-->>SDK: reply
    SDK-->>App: callback (success or error)

Three rules to remember

  1. One call at a time. A second call while one is running fails with error 5/26. A running scan counts too, so stop it first.
  2. Start the next call with main.post(...) when you call it from inside a callback. Don't call it directly.
  3. Keep the phone next to the device until the callback arrives.

0. Common arguments

These arguments appear in many functions. They mean the same thing everywhere.

Argument Type What it is
serialNumber String Serial number of the device you want to work with, as registered on the Spintly server. The SDK uses it to find the device over Bluetooth.
orgId / organisationId int ID of the organisation the device belongs to
accessorId / targetAccessorId long / int ID of the user the operation is for. For example, when adding a card or fingerprint, it is that user's accessor ID.
accessPointId int ID of the access point of the device selected for the operation
credentialId long A credential ID assigned to the user. One user can have several credential IDs, e.g. one per passcode.
callback depends on the function Your object that receives progress, success and errors. Every function explains what it receives.

// app/build.gradle.kts
android {
    compileOptions {
        isCoreLibraryDesugaringEnabled = true      // required
        sourceCompatibility = JavaVersion.VERSION_21

dependencies {
    implementation("com.spintly:configurationsdkv3:0.0.0.84-7263534")

getDefaultInstance(context)

Returns the one SDK object. Call it in Application.onCreate().

Argument Type What it is
context Context Your application context. Don't pass an Activity.

setConfiguration(configuration)

Chooses which Spintly server the SDK talks to. Call it before logIn(). The choice is saved across app restarts, so call it again only when the server changes. Pass an SdkConfiguration with either an environment and region or a URL.

Argument Type What it is
configuration SdkConfiguration A SpintlyEnvironment + SpintlyRegion, or the URL of a custom Spintly server. SpintlyRegion.US and SpintlyRegion.ME accept only SpintlyEnvironment.PRODUCTION.

getEnvironment() and getRegion() take no arguments and return what is set now, as strings (e.g. "production", "in"). Both are null when a custom URL is set.

SpintlySdkManager sdk = SpintlySdkManager.getDefaultInstance(this);
if (!"production".equals(sdk.getEnvironment()) || !"in".equals(sdk.getRegion())) {
    sdk.setConfiguration(new SdkConfiguration(SpintlyEnvironment.PRODUCTION, SpintlyRegion.IN));   // standard server
}
// or
sdk.setConfiguration(new SdkConfiguration("https://your-spintly-server.example.com"));             // custom server

Replaces the deprecated setEnvironment(environment, region) — see Deprecated setup functions.

Getting the access token (OAuth SDK)

Your app never hands its own login JWT to the Config SDK. It gives that JWT to the Spintly OAuth SDK, which exchanges it for a Spintly access token, and that access token is what every Spintly SDK accepts.

sequenceDiagram
    participant App
    participant OAuth as Spintly OAuth SDK
    participant SDK as Config SDK
    App->>OAuth: your client JWT token
    OAuth-->>App: Spintly access token
    App->>SDK: logIn(access token, callback)
    Note over App,SDK: the same access token is what the other Spintly SDKs take

What Spintly gives you. A clientId and a provider, from Spintly Support. There is a different pair per environment — the production and sandbox values are not interchangeable. The environment you pass here is the one your build targets.

String clientId    = "aabbasssd....";                  // from Spintly Support
String provider    = "assaa....";                      // from Spintly Support
String environment = SpintlyOauthManager.PRODUCTION;   // or SANDBOX
SpintlyOauthManager oauth = new SpintlyOauthManager(clientId, provider, environment);

Creating the session. getOrCreateSession reuses a valid session and only exchanges when it has to; createSession mints a new token on every call. Prefer getOrCreateSession.

oauth.getOrCreateSession(new AuthorizationCallback() {
    @Override public void onSuccess(SpintlyOauthSession session) {
        sdk.logIn(session.getAccessToken().getJWTToken(), new CompletionCallback<Void>() {
            @Override public void completed(Void result) { /* signed in — the SDK is ready */ }
            @Override public void failed(Throwable exc) { showError(exc); }
        });
    }

    @Override public void getAuthenticationDetails(AuthenticationContinuation c) {
        // The OAuth SDK needs your login parameters again — the user is signed out,
        // or every token has expired.
        AuthenticationDetails details =
                AuthenticationDetails.createWithTokenExchangeGrantType(clientToken);
        c.setAuthenticationDetails(details);
        c.continueTask();
        // If clientToken isn't available yet, hold on to the continuation and run
        // these three lines once you have it — or call getOrCreateSession again later.
    }

    @Override public void onFailure(Exception e) { /* includes network errors */ }
});
Callback method When it fires
onSuccess(session) A session is ready. session.getAccessToken().getJWTToken() is the token to pass to logIn().
getAuthenticationDetails(continuation) The OAuth SDK wants your client JWT, via a token-exchange grant. Answer it, then call continueTask().
onFailure(e) Anything failed, network errors included

The access token expires. Register a TokenRefreshHandler with setTokenRefreshHandler(): the SDK asks it for a new token when the old one is close to expiry or the server rejects it, and then re-sends the request. You don't retry calls yourself.

The user has to exist in Spintly first. The client JWT carries a unique id identifying that user, and it must already be registered with Spintly through the backend APIs — otherwise the exchange has nothing to map the user onto.

setTokenRefreshHandler(handler)

Registers your TokenRefreshHandler. Register it on every app start, before logIn().

Argument Type What it is
handler TokenRefreshHandler Your handler, or null to remove it

The SDK calls handler.refreshAuthentication(callback) on the main thread when less than 25% of the token's lifetime is left (checked at the start of each SDK call), or when a request gets HTTP 401:

You call What the SDK does
callback.completed(newToken) Saves the token and re-sends the request
callback.failed(e) The waiting call fails with e

The new token must be for the same user.

sdk.setTokenRefreshHandler(callback ->
        oauth.getOrCreateSession(new AuthorizationCallback() {
            @Override public void onSuccess(SpintlyOauthSession session) {
                callback.completed(session.getAccessToken().getJWTToken());   // SDK re-sends the request
            }
            @Override public void getAuthenticationDetails(AuthenticationContinuation c) { /* as above */ }
            @Override public void onFailure(Exception e) {
                callback.failed(e);                                          // the waiting call fails with e
            }
        }));

logIn(accessToken, callback)

Signs in with the access token from the OAuth SDK and downloads the device feature list. Signs out any previous user first, and saves the token (it survives app restarts). Call it after setConfiguration() and setTokenRefreshHandler().

Argument Type What it is
accessToken String The access token from the Spintly OAuth SDK: session.getAccessToken().getJWTToken()
callback CompletionCallback<Void> completed(null) when signed in and the SDK is ready; failed(exc) otherwise — the user is then not signed in

failed with 5/5 means the token is not a valid JWT. Any other error comes from the server call that checks the token.

Replaces the deprecated setAuthToken(token) + initiateSdk() — see Deprecated setup functions.

updateAccessToken(accessToken)

Gives the SDK a new token that your app fetched on its own (not because the handler asked). Only for the user who is already signed in — otherwise use logIn(). If the handler asked for the token, answer callback.completed(newToken) instead.

Argument Type What it is
accessToken String New access token of the signed-in user

It throws a SpintlyCFServiceException with error 5/5 if nobody is signed in, the token is not a valid JWT, or it belongs to another user, so call it inside a try/catch.

try {
    sdk.updateAccessToken(newToken);
} catch (SpintlyCFServiceException e) {
    showError(e);      // 5/5: not signed in, invalid token, or another user's token
}

Other setup functions (no arguments)

Function What it does
logOut() Signs out: stops whatever is running and clears the saved token. Call it when the user signs out of your app.
isLoggedIn() true while a token is saved (it survives app restarts), false after logOut(). It does not check whether the token has expired.
getVersion() Returns the SDK version, e.g. 0.0.0.84-7263534
stopOngoingOperation() Cancels whatever is running, e.g. when the user leaves the screen

Putting it together

// Application.onCreate() — every app start
SpintlySdkManager sdk = SpintlySdkManager.getDefaultInstance(this);
if (!"production".equals(sdk.getEnvironment()) || !"in".equals(sdk.getRegion())) {
    sdk.setConfiguration(new SdkConfiguration(SpintlyEnvironment.PRODUCTION, SpintlyRegion.IN));
}
sdk.setTokenRefreshHandler(callback ->
        oauth.getOrCreateSession(new AuthorizationCallback() {
            @Override public void onSuccess(SpintlyOauthSession session) {
                callback.completed(session.getAccessToken().getJWTToken());
            }
            @Override public void getAuthenticationDetails(AuthenticationContinuation c) { /* sign-in */ }
            @Override public void onFailure(Exception e) { callback.failed(e); }
        }));

// Sign in — once the OAuth session is ready
oauth.getOrCreateSession(new AuthorizationCallback() {
    @Override public void onSuccess(SpintlyOauthSession session) {
        sdk.logIn(session.getAccessToken().getJWTToken(), new CompletionCallback<Void>() {
            @Override public void completed(Void result) { /* ready */ }
            @Override public void failed(Throwable exc) { showError(exc); }
        });
    }
    @Override public void getAuthenticationDetails(AuthenticationContinuation c) { /* sign-in */ }
    @Override public void onFailure(Exception e) { /* show sign-in error */ }
});

// User signs out of your app
sdk.logOut();

All callbacks arrive on the main thread. To start the next call from a callback, use main.post(...):

Handler main = new Handler(Looper.getMainLooper());

Deprecated setup functions

⚠️ Deprecated — will be removed in a future version. These still work today, but don't use them in new code. Move to the new functions now.

Deprecated Use instead What changes
setEnvironment(environment, region) setConfiguration(configuration) Same environments and regions, as enums (SpintlyEnvironment, SpintlyRegion) instead of strings. Can also take a custom server URL.
setAuthToken(token) logIn(accessToken, callback) Tells you if signing in worked. The token is saved across app restarts.
initiateSdk() logIn(accessToken, callback) logIn() downloads the device feature list itself.
Token expires → calls fail with 9/2, app refreshes with setAuthToken and retries setTokenRefreshHandler(handler), updateAccessToken(accessToken) The SDK asks your handler for a new token and re-sends the request

Migrating

// Before (deprecated)
sdk.setEnvironment("production", "in");
sdk.setAuthToken(session.getAccessToken().getJWTToken());
sdk.initiateSdk();

// After
sdk.setConfiguration(new SdkConfiguration(SpintlyEnvironment.PRODUCTION, SpintlyRegion.IN));
sdk.setTokenRefreshHandler(handler);
sdk.logIn(session.getAccessToken().getJWTToken(), callback);

getEnvironment() and getRegion() are not deprecated; they return what was set by either function.

startConfigurableDevicesScan(callback)

Lists new, not-yet-set-up devices near the phone.

Argument Type What it is
callback SpintlySdkScanCallback Override onConfigurableDeviceListUpdated(Set<ScannedBleDevice> devices) for the list, which refreshes about once a second, and onFailure(e) for errors

Each item in the list is a ScannedBleDevice — use getName(), getMacAddress(), getRssi() (signal strength) and getSerialNumber(). getSerialNumber() is nullable: the SDK fills it in when it can read the serial number out of the device's advertisement, and leaves it null when the advertisement doesn't carry one. Null-check it before showing it or matching on it:

@Override public void onConfigurableDeviceListUpdated(Set<ScannedBleDevice> devices) {
    for (ScannedBleDevice d : devices) {
        String serial = d.getSerialNumber();          // may be null
        String label  = serial != null ? serial : d.getName();
        showRow(label, d.getRssi());
    }
}

configureDevice(serialNumber, callback)

Sets up the device in a BLE mesh network and informs backend about it. If the device's firmware is too old, the SDK updates it first.

Argument Type What it is
serialNumber String The device picked from the scan. It must already be registered on the server.
callback SpintlyCompletionAndFirmwareUpdateStatusCallback<Void> Gives you onStatusUpdate(status, message), onConnectionStatusUpdate(status), onFirmwareTransferStatus(step, totalSteps, percent), then completed(null) or failed(e) 
sdk.stopScan(new SpintlyCompletionCallback<Void>() {
    @Override public void completed(Void r) { main.post(() -> configure(serialNumber)); }
    @Override public void failed(SpintlyCFServiceException e) { showError(e); }
});

void configure(String serialNumber) {
    sdk.configureDevice(serialNumber, new SpintlyCompletionAndFirmwareUpdateStatusCallback<Void>() {
        @Override public void onStatusUpdate(OperationStatus status, String message) { showStatus(message); }
        @Override public void onConnectionStatusUpdate(ContinuousConnectionStatus status) { }
        @Override public void onFirmwareTransferStatus(int step, int totalSteps, float percent) { showProgress(step, totalSteps, percent); }
        @Override public void completed(Void r) { /* done → set master passcode */ }
        @Override public void failed(SpintlyCFServiceException e) { showError(e); }
    });
}

Force update of a BLE beacon

A new BLE beacon (BLE remote) comes from the factory with factory firmware, not the firmware Spintly devices work with. Before the beacon can be used, it has to be brought up to a base firmware version. That is what the force update does: it finds the beacon over Bluetooth while it is in update (DFU) mode and installs the base firmware on it.

11. Reset device

There are two ways to factory-reset a device:

Function How it resets Status
resetDevice() Over Bluetooth, with the phone next to the device Available
remoteResetDevice() Through the Spintly backend, which reaches the device via its gateway Planned

Start with resetDevice(). The phone talks to the device directly, so the reset either happens while the installer is standing there or it fails there and then.

If resetDevice() fails, the app has the choice of calling remoteResetDevice() with the same serial number. That choice is the app's to make, on any error rather than a particular one — Bluetooth off, permission missing, the device out of range, asleep, or simply not answering all end up as different codes, and none of them mean the remote route will fail too. Whether to offer it is up to the app: it might try the remote reset straight away, put a "reset remotely instead" button in front of the user, or just report the failure and leave it.

Resetting a gateway

As with a device (section 11), there are two ways to reset a gateway:

13. Errors

Every error is a SpintlyCFServiceException with a domain and a code. In this guide, 5/22 means domain 5, code 22.

@Override public void failed(SpintlyCFServiceException e) {
    Log.e("Spintly", e.getDomain() + "/" + e.getCode() + " " + e.getMessage());
}

The domain/code pair is the stable identity of an error — switch on that, never on the message text, which may be reworded. getMessage() is for humans; getRequestId() is what Spintly needs to find the failure in their logs, so log it with every error and include it in bug reports.

Handling errors in one place

Because the useful distinction is what the user should do next, not which function failed, one helper covers most screens:

void showError(SpintlyCFServiceException e) {
    Log.e("Spintly", e.getDomain() + "/" + e.getCode() + " " + e.getMessage()
            + " requestId=" + e.getRequestId());

    switch (e.getDomain()) {
        case 4:                                     // server business error
            toast(e.getMessage());                  // safe to show as-is
            return;
        case 9:
            toast(e.getCode() == 2 ? "Please sign in again" : "Check your internet connection");
            return;
    }
    if (e.getDomain() == 5 && e.getCode() == 5)  { toast(e.getMessage()); return; }   // BT / permission
    if (e.getDomain() == 5 && e.getCode() == 22) { toast("Move closer to the device"); return; }
    if (e.getDomain() == 5 && e.getCode() == 26) { toast("Please wait for the current step"); return; }

    toast("Something went wrong. Please try again.");
}

Everything not in the tables above is an internal or protocol-level failure — a device replying in an unexpected state, an unsupported message version, a decode mismatch. There is no useful per-code action for these: show a generic retry message, and report getDomain(), getCode() and getRequestId() to Spintly.
